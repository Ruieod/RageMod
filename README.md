# RageMod

Два внутренних чита в одном репозитории. Общий код — imgui, шрифт, стиль меню,
подход к оффсетам: все магические числа живут в одном заголовке на модуль,
логика их не знает.

| | цель | статус |
|---|---|---|
| [`standoff2/`](standoff2/) | `com.axlebolt.standoff2` 1.0.0 arm64-v8a, Unity il2cpp | собирается, в игре не проверен — акк под баном Play Integrity |
| [`cs2/`](cs2/) | `cs2.exe` x64, Source 2 | собирается, в игре не проверен — нет винды и `client.dll` |

---

## standoff2 — Android, arm64, internal

Код il2cpp у SO2 слит в `libunity.so`, экспортов `il2cpp_*` нет, поэтому ни одного
рантайм-лукапа класса: всё по RVA и смещениям полей из `src/offsets.h`, снятым с
дампа конкретной сборки (`libunity.so` sha256 `a5d530e0…f33e0f` — совпал с его apk
байт в байт).

**Что сделано**

- ESP: бокс, скелет по `HitBoxCollider[]`, HP, дистанция, снаплайны, фильтры;
- silent aim двумя путями — подмена `HitTransform` и override уже готовых лучей
  хит-каста, переключатель в меню (какой из них реально переписывает выстрел —
  проверяется за один раунд);
- visible aim записью сетевых кватернионов `eir`;
- auto fire через хук геттера кнопки, no recoil через `RecoilState`;
- chams материалами из `CharacterBindings` + render queue;
- третье лицо отводом камеры после кадрового тика;
- меню ImGui поверх `eglSwapBuffers`, ввод из `UnityEngine.Input` (без рута) или
  `/dev/input` (с рутом), под меню ввод глушится хуками `znn.rpcp` / `znn.qvli`.

**Семь точек перехвата** — таблица RVA в [`standoff2/README.md`](standoff2/README.md).
Прологи всех целей PC-независимы (проверено дизасмом), поэтому inline-хук — простой
16-байтный патч `ldr x16,#8 / br x16 / .quad`, без движка хуков. Если после патча игры
пролог станет PC-зависимым, хук откажется ставиться и напишет в лог, а не испортит код.

**Загрузка без рута** — подмена `libmain.so`. Dex не трогаем: оригинал переименовывается
в `libmain_orig.so`, на его место кладётся наша либа с пропатченным `SONAME`, наш
`JNI_OnLoad` стартует чит и пробрасывает вызов в оригинал. Меняются ровно две записи zip.

**Чем кончилось.** Пересобранный apk подписан не ключом Axlebolt, Play Integrity это
видит на сервере и акк улетает в бан сразу после входа — проверено на практике, два раза.
Клиентски не обходится. Нужен рут + нетронутый apk; на vivo X200 Pro (Dimensity 9400)
загрузчик заперт, BROM-эксплойта нет, так что на этом телефоне ветка тупиковая.

**Последняя правка** (`95091f1`): игровые хуки больше не ставятся на старте — патч 16 байт
в функции, которую прямо сейчас исполняет другой поток, ронял игру на 1.3% загрузки.
Теперь на старте поднимается только оверлей, игровые хуки включаются кнопкой в меню,
когда игра уже живёт. Заодно `class_name` перестал ходить в `/proc/self/maps` на каждый
байт имени — одна проверка на буфер вместо сотен под мьютексом каждый кадр.

```bash
ANDROID_NDK=.../android-ndk-r27c ./build.sh       # -> build/arm64/libragemod.so
./tools/pack_apk.sh game.apks                     # -> dist/standoff2-ragemod.apk
./tools/preview/build_preview.sh 3 2340 1080      # меню в png, без телефона
```

## cs2 — Windows, x64, internal

Оффсеты не пишутся руками: `tools/update_offsets.py` тянет дамп
[cs2-dumper](https://github.com/a2x/cs2-dumper) и генерит `src/offsets_gen.h`.
Если Valve переименовала поле — скрипт падает с его именем, а не кладёт ноль в бинарь.

![menu](cs2/docs/menu-ragebot.png)

**Что сделано**

| | |
|---|---|
| Ragebot | аим по костям, FOV, авто-огонь, упреждение по скорости цели |
| Trigger | цель под прицелом из `m_iIDEntIndex` — игра считает её сама, свой рейкаст не нужен |
| Movement | bunny hop по биту `FL_ONGROUND` в `m_fFlags` |
| Players | ESP (бокс уголками, скелет, HP, ник, дистанция), glow через `CGlowProperty` с раздельными цветами для видимых и закрытых |
| Hit effects | хит-маркер дугами, всплывающий урон, плашка на добивание; ловим просадку HP врага, авторство — по своему счётчику выстрелов |
| HUD | ватермарка-пилюля, список активных биндов с состоянием, скруглённые плашки с тенью |
| World | night mode с настраиваемым оттенком, FOV-круг |
| Skins | `m_nFallbackPaintKit` / seed / wear / StatTrak на активном оружии |
| Меню | сайдбар с иконками и группами, шапка Save / Global, панели-группы, свои тумблеры, комбо, слайдеры, пикер цвета; бинд — кружок слева от тумблера |

Ничего не включено на старте, кроме ESP. Меню — `INSERT`, выгрузка — `END`,
конфиг — `%APPDATA%\ragemod_cs2.json`.

**Последняя правка** (`91dc7af`) — инфраструктура под то, чего нет в дампе:

- `src/scan.cpp` — поиск по `.text` масками в формате IDA, xref на строковый литерал
  (строка в `.rdata` → `lea reg,[rip+disp]` на неё), поиск начала функции по паддингу
  и типовым прологам, дамп vtable в текстовый файл с модулем и RVA каждой записи;
- `src/sigs.cpp` — индекс `GetUserCmd` и смещения внутрь `CUserCmd` в
  `Documents\RageMod\ragemod_sigs.ini`, перечитываются кнопкой, без пересборки dll;
- `src/antiaim.cpp` + вкладка в меню — static / jitter / spin / sway, режимы pitch,
  разворот спиной к ближайшему врагу.

Сборка после последней правки `scan.cpp` (добавил `psapi.h`) до конца не доведена —
**не проверял**, `.dll` в `build/win64` от 29-го.

```bash
./build.sh                          # -> build/win64/ragemod_cs2.dll
python3 tools/update_offsets.py     # после патча игры
./tools/preview/build_preview.sh 2 1920 1080
```

## Что проверено, а что нет

Проверено здесь: обе либы собираются, оффсеты сверены с дампами, вёрстка меню —
растеризацией реального кадра imgui в png (картинки в `docs/`). Хэш `libunity.so`
из его apk совпал с хэшем дампа, значит RVA для SO2 верные.

Не проверено в игре ничего: ни одного запуска ни под Android, ни под Windows.
Подробные списки «что именно под вопросом» — в README каждого модуля, там же
инструкции под новый патч игры.

## Чего в cs2 нет и почему

Честный silent aim, третье лицо и настоящие chams упираются в одно и то же:
нужен перехват `CUserCmd` и функции камеры, а для поиска паттернов нужен сам
`client.dll`. Пока его нет:

- silent — это снап на кадр выстрела с возвратом угла;
- вместо chams — glow типа 3 с разными цветами;
- anti-aim пишет `dwViewAngles`, то есть крутит и камеру тоже, и годится только
  для дм. Как только `ragemod_sigs.ini` заполнен — переключается на `CUserCmd`
  и камера остаётся на месте.

## Про анти-читы

Коротко и без иллюзий: ни один из двух модулей не «андетект».

- **SO2** — Play Integrity проверяет подпись apk на сервере, пересобранный apk
  даёт бан на входе. Это не обходится со стороны клиента.
- **CS2** — сводка на 2026-10-30. Valve подробностей не публикует, всё ниже из
  вторичных источников и не проверено на практике, ссылки в пунктах:
  - **VAC Live** — серверная проверка прямо в матче, поведенческий анализ, драйвера
    на клиенте нет ([SteamDB](https://steamdb.com/en/news/cs2-anti-cheat-update-vac-live)).
    По данным датамайнера в январе 2026 вернулась на полную силу, с ложными банами
    и откатом ([ggscore](https://ggscore.com/en/csgo/news/74878)).
  - **VACnet** — по сообщению коммерческого блога, 29.07.2026 Valve закрыла обход,
    на котором держались рейдж-читы, без патчноутов
    ([ExitLag](https://www.exitlag.com/blog/vacnet-update-cs2/)); подтверждения
    из второго источника нет.
  - **Волны** — март 2026: ~960k ферм-аккаунтов за день
    ([esportslegal](https://esportslegal.news/2026/04/01/valve-1-million-accounts-cs2-ban-wave/));
    август 2026: ~30k game-банов, в основном фарм, не читы. По октябрю ничего не нашёл.
  - **Trust Factor** — скрытый скор для матчмейкинга, критерии не опубликованы.
  - **Ревью демок** — статус в CS2 неясен: по одному источнику, закрытый пул
    доверенных ревьюеров вместо общественного Overwatch.

  Прежняя формулировка «VAC не ловит бхоп или silent как поведение» не держится:
  серверный анализ смотрит именно на поведение. Ragebot и anti-aim — самое заметное
  и для него, и для демки.

Подмена записи в vtable вместо инлайн-патча и запись в структуры кнопок вместо
`SendInput` уменьшают поверхность клиента, но гарантий не дают. Играть — только с
акка, который не жалко.
